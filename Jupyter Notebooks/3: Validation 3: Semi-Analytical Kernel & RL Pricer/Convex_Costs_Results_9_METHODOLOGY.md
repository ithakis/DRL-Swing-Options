# Convex Costs Results 9 — Methodology

How the paper's headline table (`Convex Costs Results 9.csv`) is generated by
[`gen_results9_v67.py`](gen_results9_v67.py). Each `(c, \gamma)` cell prices three methods on the
**same** out-of-sample (OOS) paths and reports each as a bootstrap mean with a 95% confidence interval.

## The three methods

Each method is run at its own **plateau budget** (the smallest budget at which it stops improving),
so the table compares each method at its best operating point.

- **LSM-D** — full-state Least-Squares Monte Carlo, Chebyshev degree-2 basis, `M = 5` action levels; fit on **32,768** training paths (Python, `src/lsm_swing_pricer`).
- **AC-sample** — v67 actor–critic, **no kernel** (single-sample TD bootstrap); trained for **32,768** episodes (C++, `build_v67_nokernel`).
- **AC-kernel** — v67 actor–critic, **semi-analytical kernel** target; trained for **4,096** episodes (C++, `build_v67_kernel`).

> The kernel's episode count is a **state-space coverage** budget, not a Monte-Carlo sample size: its
> critic target is an analytical expectation over the HHK transition kernel, so paths choose *where* to
> learn, not *how precisely*. This is why it plateaus ~8× sooner than AC-sample.

## What is being estimated

All three learn a **feasible (sub-optimal) exercise policy** $\pi$, then Monte-Carlo value it. Each is
therefore a **low-biased lower bound** on the unknown true price, so "method A > method B" means "A's
policy captures more value." The price of a fixed policy on $N$ OOS paths is

```math
\hat V(\pi) = \frac{1}{N}\sum_{i=1}^{N} \sum_{t} D_t\,\big(q_{t}^{(i)}(S_t^{(i)}-K)_+ - c\,(q_t^{(i)})^{\gamma}\big)
```

where $D_t$ is the discount factor and $q_t$ the exercised quantity under $\pi$.

## Paired out-of-sample design (common random numbers)

For each run index $k$ (seeds $11\ldots18$), **one** OOS set of **65,536** paths is generated at
eval-seed $=\text{seed}_k+777$ and **shared** across all three methods.

- The C++ kernel run dumps the OOS once (`SXYP` blob); the no-kernel build reproduces it bit-identically (HHK sim is independent of the kernel, `--threads 1`), and Python-LSM prices the same dumped paths.
- Pricing every method on the identical OOS is **common random numbers** — it cancels OOS noise in the method-vs-method comparison.

## Per-cell protocol

One cell at a time (keeps RAM ≤ 8 GB; OOS dumps deleted after the row is written):

1. Run the 8 kernel + 8 no-kernel C++ jobs in parallel (8 cores, 1 thread each), dumping OOS$_k$.
2. Fit + price LSM-D on each OOS$_k$ (own training paths, seed $700+k$).
3. Bootstrap each method's mean price and the paired $\Delta\%$; append one CSV row.

## Reported statistic: BCa bootstrap (95%)

Per (cell, method) we have 8 paired prices $x_1,\ldots,x_8$. We report the mean and a
**bias-corrected and accelerated (BCa)** interval (asymmetric; correctly calibrated at small $n$,
unlike a $\pm 1.96\,\text{SE}$ normal fit). With bootstrap means $\hat\theta^{*}_b$:

- Bias correction $z_0 = \Phi^{-1}\!\big(\tfrac{\#\{\hat\theta^{*}_b < \bar x\}}{B}\big)$.
- Acceleration $a$ from the jackknife values $x_{(\cdot)}$:

```math
a = \frac{\sum_i (\bar x_{(\cdot)} - x_{(i)})^3}{6\,\big[\sum_i (\bar x_{(\cdot)} - x_{(i)})^2\big]^{3/2}}
```

- Interval endpoints are the $\alpha_{\text{lo}},\alpha_{\text{hi}}$ bootstrap quantiles, with

```math
\alpha = \Phi\!\left(z_0 + \frac{z_0 + z_{\alpha}}{1 - a\,(z_0 + z_{\alpha})}\right),\qquad z_{\alpha}=\Phi^{-1}(\alpha).
```

We use $B = 2000$ resamples and also report the per-seed standard deviation (run-to-run dispersion).

## Paired improvement $\Delta\%$

Because methods share OOS$_k$, the improvement is computed **per run** and then bootstrapped (cancels
the shared OOS noise):

```math
\Delta_k = 100\left(\frac{\hat V^{\text{RL}}_k}{\hat V^{\text{LSM}}_k} - 1\right),\qquad k = 1,\ldots,8.
```

## Grid

29 cells: $(c=0,\ \gamma=1)$ plus $c \in \{0.01, 0.02, 0.04, 0.05, 0.08, 0.10, 0.15\}\times\gamma\in\{1, 1.5, 2, 3\}$.

## Output columns (`Convex Costs Results 9.csv`)

One row per cell; the paper just rounds and converts to LaTeX.

- **Budgets:** `LSM_fit_paths`, `ACsample_ep`, `ACkernel_ep`, `n_oos`, `n_seeds`.
- **Per method:** `{LSM,ACsample,ACkernel}_{mean,lo,hi,sd}` (BCa interval `[lo, hi]` + seed SD).
- **Paired Δ%:** `{ACsample,ACkernel}_delta_{pct,lo,hi}`.

## Reproducibility & runtime

- **Float32** throughout the C++ pricer and OOS dumps; LSM regression upcasts the f32 paths to f64.
- **Restartable:** completed cells are skipped via the CSV; partial cells reuse the on-disk C++/LSM caches.
- **Live:** rows are flushed on write, with a per-cell `[i/29] … | elapsed | ETA` progress line.
